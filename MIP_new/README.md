# MIP package

This package contains mixed-integer programming formulations for the sonar-placement optimization problem. It is designed to use the trained model and the bound precomputations from the sibling `bounds_new` package to search for good or optimal placement decisions under a fixed map, goal, and sonar budget.

The package contains the following modules:

- `base_MILP.py`: shared MILP construction utilities and reusable formulations
- `MILP_unknown_as_decision_var.py`: joint formulation where unknown-sonar choices are treated as decision variables
- `MILP_robust.py`: robust optimization formulation
- `cli.py`: command-line interface for launching the solver

## Purpose

The MIP layer is used to solve placement problems over the hex-grid environment under constraints such as:

- fixed number of sonar placements
- forbidden regions around the start and goal
- fixed obstacle layout
- optional unknown-sonar decision variables
- model-based output or robustness constraints

This is an optimization layer built on top of the trained predictor, rather than a pure sampling or rollout-based method.

## Main idea

The MIP is built from the network’s linearized representation:

- the model’s activations are represented as variables and constraints
- the sonar placement variables decide where sensors are placed
- the unknown-sonar variables may represent uncertainty about which sonars are hidden or unobserved
- the objective is to select a placement that improves the modeled predictive performance or satisfies a robust criterion

The formulations rely on bound information generated by `bounds_new` so that the optimization remains tractable.

## Supported modes

The CLI in `MIP_new/cli.py` supports the following modes:

```bash
python -m MIP_new.cli --mode joint ...
python -m MIP_new.cli --mode robust ...
```

The typical inputs are:

- model checkpoint path
- bounds directory
- start and goal indices
- sonar count
- unknown-sonar count
- obstacle list
- forbidden radius
- rows and columns
- optional time limit and MIP gap

## Example usage

```bash
python -m MIP_new.cli \
  --mode joint \
  --checkpoint model.pth \
  --bounds-dir tight_bounds/model_x \
  --start 0 \
  --goal 399 \
  --sonar-number 8 \
  --unknown-number 2 \
  --forbidden-radius 6 \
  --rows 20 \
  --columns 20
```

or

```bash
python -m MIP_new.cli \
  --mode robust \
  --checkpoint model.pth \
  --bounds-dir tight_bounds/model_x \
  --start 0 \
  --goal 399 \
  --sonar-number 8 \
  --unknown-number 2 \
  --forbidden-radius 6 \
  --rows 20 \
  --columns 20
```

## Gurobi requirement

This package uses Gurobi as the underlying MIP solver. The project is therefore dependent on a working `gurobipy` installation for exact optimization.

If the environment is not configured correctly, the MILP construction or solve step will fail at runtime.

## Model and bounds integration

The optimization uses files produced by the `bounds_new` package, especially:

- `c_z.npy`
- `const_z.npy`
- `local_bounds.npz`
- optional `global_bounds.npz`

These are loaded from the bounds directory and used to build and tighten the MILP. Without these artifacts, the optimization cannot be constructed in the intended form.

## Joint vs robust formulation

### Joint formulation

`MILP_unknown_as_decision_var.py` models placement decisions and unknown-sonar decisions jointly. This is the more explicit formulation when the unknown-sonar pattern itself is part of the optimization problem.

### Robust formulation

`MILP_robust.py` is designed for robust optimization settings, where the solver accounts for uncertainty in a more adversarial or worst-case manner.

## Output

The solver returns a result dictionary containing the selected placement variables, unknown-sonar assignments, and any optimization metadata. The CLI can optionally save those placements to a `.npz` file using the `--output` argument.

## Summary

The `MIP_new` package is the optimization layer of the project. It turns the trained model and the bound information into an exact or robust optimization problem over sonar placements, enabling principled placement selection in the same map and sensing setting used by the dataset and trainer packages.
