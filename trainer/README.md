# Trainer package

This package contains the training pipeline for the local-global network used to predict planning outcomes from the hex-grid feature maps generated by the dataset package.

The training stack is organized around:

- `data_builder.py`: dataset loading and dataloader construction
- `model.py`: local-global neural model
- `loss.py`: custom loss functions for MSE, CVaR, and annealed extreme-tail objectives
- `trainer.py`: training and validation loop
- `cli.py`: command-line entry point
- `validate.py`: model evaluation and prediction visualization
- `plot.py`: plotting utilities for predictions and diagnostics

## Overview

The network consumes per-cell local features and a small global context vector, then predicts a scalar target for each relevant cell or for a selected subset of target cells. The design is intended for structured prediction over a fixed-size hex-grid map.

The training data is expected to come from a parts directory produced by the dataset generation pipeline. Each row contains:

- local feature tensor per cell
- global context vector summarizing the instance
- target vector computed from the outputs for the chosen cells

## Data loading

The main dataset abstraction is `PartsDataset` in `data_builder.py`.

It assumes a dataset directory with:

```text
meta.json
cost.npy
obstacle_placement.npy
sonar_placement.npy
...
outputs.npy
reachable_mask.npy
```

The loader reads the arrays using memory maps and concatenates the requested local feature fields into a single tensor of shape:

```text
(B, N, K)
```

where:

- `B` = batch size
- `N` = total number of cells in the grid
- `K` = combined local feature dimension

The global context is concatenated from fields such as:

- `goal_onehot`
- `obstacle_number`
- `sonar_number`
- `start_as_known_number`
- `start_as_unknown_number`

The target is the selected output slice, typically the reachable cells or a reduced set of training cells.

## Model architecture

The model in `model.py` is a `LocalGlobalNet`.

It does the following:

1. applies a per-cell local MLP to every grid cell
2. produces a compact local representation for each cell
3. flattens these local outputs across the map
4. concatenates the flattened local representation with the global context
5. passes the result through a global MLP
6. returns the final prediction vector

The network is designed to operate on a fixed 20x20 hex-grid layout, but the architecture can be re-used for other fixed grid sizes by adjusting the dimensions.

## Loss functions

The package implements several objective functions in `loss.py`:

- `MSELoss`: standard mean squared error
- `CVaRLoss`: tail-risk objective over the highest-error samples
- `AnnealedLoss`: blends MSE and CVaR over training epochs
- `ExtremeMSELoss`: focuses on the upper tail of the target distribution
- `AnnealedExtremeMSELoss`: anneals from ordinary MSE to extreme-tail MSE
- `AnnealedRandomMSELoss`: anneals from full-data MSE to random subset MSE
- `MiddleMSELoss`: focuses on samples near the median target value

These losses are used to emphasize different portions of the target distribution depending on the dataset and training regime.

## Training loop

The `Trainer` class in `trainer.py` manages:

- batching and device transfer
- forward pass
- loss computation
- backpropagation
- optimizer steps
- validation metrics and checkpointing

It supports a validation mode that computes several measures including:

- MSE
- CVaR
- extreme-target metric
- random-subsample metric
- median-centered metric

This is useful when selecting the best checkpoint under non-standard loss schedules.

## CLI usage

The primary entry point is:

```bash
python -m trainer.cli --help
```

Typical usage:

```bash
python -m trainer.cli \
  --data data/best_dataset_known_and_unknown_complete_parts \
  --epochs 100 \
  --batch 64 \
  --lr 1e-3 \
  --loss extreme \
  --save-path best_model.pt \
  --last-save-path last_model.pt
```

Key arguments:

- `--data`: dataset directory to train on
- `--epochs`: number of training epochs
- `--batch`: batch size
- `--lr`: learning rate
- `--max-samples`: limit the number of samples used before train/validation split
- `--val-fraction`: validation fraction
- `--loss`: objective to optimize (`mse`, `cvar`, `annealed`, `extreme`, `random`, `middle`)
- `--train_cells`: optional subset of target cells to train on
- `--save-path` and `--last-save-path`: checkpoint locations

## Validation and plotting

`validate.py` loads a trained model and evaluates it on a dataset. It can also call `plot_predictions(...)` from `plot.py` to visualize groundtruth vs. predictions.

Example:

```bash
python -m trainer.validate \
  --data data/my_dataset_parts \
  --model best_model.pt \
  --batch 128 \
  --train_cells 0
```

This is useful for checking both numeric performance and qualitative behavior on the structured prediction target.

## Notes on training data assumptions

The trainer expects the dataset arrays to follow the feature schema produced by the environment and dataset packages. In practice this means:

- the local feature tensor must match the network input dimension
- the global context vector must match the expected size
- the target vector must correspond to the selected training cells

If `train_cells` is set, the model is trained only on that subset of outputs. Otherwise, it uses all reachable cells for each sample.

## Summary

The trainer package is the learning layer of the project: it turns the structured environmental features into a neural model that predicts map-level planning outcomes under different objective functions and training regimes. It is designed specifically for the synthetic datasets generated by the dataset package and the simulator defined in the environment package.
